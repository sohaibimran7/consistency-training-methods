## Shared laptop Isambard job coordination

- Use `/Users/work/.local/bin/isambard-jobs` for new agent-owned Isambard-AI Phase 2 submissions. Use its default shared state directory; never create a per-task/worktree queue to obtain another interactive slot.
- Start with `isambard-jobs status`, which reads the shared cache. Use `tick` for a coordinated refresh/dispatch or `enqueue MANIFEST --start` for a bounded local collector. Do not run independent scheduler polling loops; the controller serializes snapshot attempts at least 60 seconds apart across this account's tasks.
- Prepare RMCT/Gemma requests with the maintained controller profiles. Declare actual writable output/checkpoint locations and freeze remote scientific code/configuration before enqueueing. The captured launch script does not freeze its imported code or runtime. Store only non-secret configuration in manifests.
- Interactive capacity is one submitted job total per user, pending OR running. Keep interactive work to bounded diagnostics/exploration; use normal `workq` batch jobs for sustained training and full evaluation. Do not start new remote interactive brokers or chains, or bypass admission with direct `srun`/`sbatch` from another task.
- Preserve existing jobs during migration. Register legacy jobs with `protect` and their real canonical output roots; this observes them without changing them. Do not cancel, hold, restart, or alter another task's jobs. Cancellation of a controller-managed job requires explicit authorization and its matching owner.
- After an uncertain submission, keep its request and output ownership intact and reconcile by the recorded job ID/token. Never retry automatically or infer completion from absence in the live queue. `resolve-unsubmitted` requires an explicit investigated attestation that no job was submitted; never use it as automatic recovery.
- The local collector closes every SSH connection and stops on access/transport failures. It does not renew credentials. Restore access using the existing on-demand authentication workflow, then resume with `isambard-jobs start`. Submitted batch jobs continue independently of the laptop connection.
- Workflow, profiles, recovery, and scope limitations: [Shared Isambard job controller](/Users/work/.local/share/ctm-isambard/JOBS.md). The installed copies survive worktree removal. Canonical controller source is in `infra/isambard/` in the authentication repair checkout.
